> **版本**：v1.0（2026-11-10）
> **作用**：把本项目从 `shiji-kb` 继承的知识**内化**为本仓库自足的参考资料。
> 读者不需要打开 `shiji-kb` 也能理解本项目的设计依据。
> **仅在需要追溯原始出处时**才去查那个仓库。

## 一、为什么要有这份文档

本项目的标注体系不是凭空设计的，它继承自 `shiji-kb`（《史记》知识库）——
一个把 130 卷《史记》做成可检索语义库的项目。

继承是对的，但**依赖外部仓库学习基础知识是脆弱的**：
- 那个仓库会变
- 它的语境是《史记》，不是对联
- 新来的 Agent 不该为了改一行词典去读别人的 CLAUDE.md

所以这份文档做一件事：**把继承的东西讲清楚，并说明本项目做了哪些不同的选择**。

**阅读顺序建议**：
1. 先读本文（知道来龙去脉）
2. 再读 `skills/SKILL_01` 和 `SKILL_03`（知道怎么用）
3. 只有想追根源时，才看文末的原始文件清单

## 三、L1：为什么是 Token 而不是 XML

这是本体系最根本的一个选择，必须理解清楚。

### 3.1 四种方案的对比

`shiji-kb` 的 `00-META-08_标注体系设计.md` 记录了这个决策过程。

| 方案 | 示例 | 优点 | 致命缺点 |
|---|---|---|---|
| **XML/TEI** | `<persName>刘邦</persName>` | 学术标准、工具链成熟 | **冗长**：正文被标记淹没 |
| **HTML** | `<span class="person">刘邦</span>` | 可渲染 | 同样冗长，且混合了表现层 |
| **Markdown 扩展** | `**刘邦**{:.person}` | 简短 | 非标准、解析器各异 |
| **Token（本项目）** | `〖@刘邦〗` | 极短、位置稳定、易正则 | 需自建解析器 |

### 3.2 那个决定性的实验

`shiji-kb` 的 `00-META-07_可读性.md` 记录了一次真实的对比测试：

| 方案 | 字符膨胀 | 阅读时间 |
|---|---|---|
| XML | **+240%** | 45 秒 |
| Token | **+35%** | 18 秒 |

结论：

> 古籍标注的第一读者是**人**，不是机器。
> 如果标记让原文不可读，标注本身就失去了意义。

### 3.3 一次真实的回退

`shiji-kb` 曾经尝试过 HTML 标记，理由是"浏览器能直接显示颜色"。
结果原文被 `<span>` 撕成碎片，**随即回退**。

这段历史的价值：

> **"能渲染"不是选择标记格式的理由。**
> 渲染是**下游**的事（本项目由 `render_yinglian.py` 做），
> 不该污染**上游**的标注层。

### 3.4 本项目的实践

```markdown
尝闻〖@纪文达|纪昀〗师言：〖^楹帖〗始于〖^桃符〗，蜀〖@孟昶〗"余庆""长春"一联最古。
```

对比 XML：

```xml
尝闻<persName ref="纪昀">纪文达</persName>师言：<term type="couplet">楹帖</term>
始于<term type="taofu">桃符</term>，蜀<persName>孟昶</persName>……
```

Token 版的可读性明显更好。**这就是选择它的全部理由。**

### 3.5 代价（必须承认）

| 代价 | 缓解方式 |
|---|---|
| 非标准格式 | 本仓库 `SPEC` 完整定义语法 |
| 需要自建解析器 | `strip_markup()` 已实现并通过反演校验 |
| 不能直接被 TEI 工具读 | `structure.json` 可无损导出 TEI（见 BOOK 第十六章） |

## 四、L1：三个符号集合必须分离

来自 `shiji-kb` 的 `SKILL_01g_标注符号集合原则.md`。

### 4.1 原则

**不同用途的标记，使用不重叠的定界符。**

| 集合 | 用途 | 本项目用法 |
|---|---|---|
| `〖〗` | 实体标注 | 18 类实体 |
| `〘〙` | 词汇/语义层 | **保留未用** |
| `⟦⟧` | 语法/动作层 | **保留未用**（见 §六） |

### 4.2 为什么必须分离

如果实体和动作都用 `〖〗`，解析器无法区分：

```markdown
〖@刘邦〗〖攻〗〖=咸阳〗     ← 谁是实体？谁是动作？
```

分离后：

```markdown
〖@刘邦〗⟦◈攻⟧〖=咸阳〗     ← 一目了然
```

### 4.3 `shiji-kb` 的诚实评估

那份 SKILL 里写了三条警告（大意）：

1. 符号集合多了，解析复杂度上升
2. 某些符号在纯文本环境下易与标点混淆
3. 实践中往往只用到一两个集合

**本项目的应对**：只用 `〖〗`，另两个**保留但不用**——
保留了未来扩展的位置，又不增加当前复杂度。

## 五、L2：Purple Numbers 的来历

### 5.1 起源

Purple Numbers 是 **Douglas Engelbart**（鼠标发明者）在 1960 年代
"Augmenting Human Intellect" 项目中提出的概念。

核心思想：

> **文档的每个可引用单元都应该有一个稳定的地址。**
> 地址不依赖文档顺序（插入新内容不改变旧地址）。

### 5.2 传统做法 vs 本项目

| | 传统 | 本项目 |
|---|---|---|
| 编号 | 顺序编号（1,2,3…） | **层级编号**（`1.3.2.1`） |
| 插入新段 | 后面全部重编号 | 不影响既有编号 |
| 定位 | 只知"第几段" | 知"第几书第几卷第几条第几段" |

### 5.3 本项目的编号规则

```
[1]          书（楹联丛话）
[1.3]        卷/门类（故事）
[1.3.1]      条目（一个话题单元）
[1.3.1.1]    段落（含续行合并后的完整段）
```

**生成位置**：`yinglian_lib.py` 的 `assign_pn()`，
在**结构切分完成后**统一分配。

**为什么不能在最后加**：
编号被 `couplets.json` 的 `source_ref` 引用，
若最后才定编号，联语与段落的对应关系会错乱。

## 六、L4：为什么没有动词层（重要）

这是本项目**主动拒绝**继承的部分。

### 6.1 `shiji-kb` 的动词层

`shiji-kb` 有 `⟦◈杀⟧`、`⟦◈伐⟧`、`⟦◈立⟧` 这类语法标注，
用于抽取《史记》中的"谁对谁做了什么"。

词表约 42 个，**几乎全是军事/政治动词**。

### 6.2 为什么在联话里失效

**原因一：词表错位**

联话的动作是"题联""书楹""集句"——复合词，一个都不在表里。

**原因二：文体错位**

联话是**描写性/评点性**文本（记亭台、品对联），
不是**叙事性**文本（记战争、记政变）。

**原因三：会造成嵌套**

若 `⟦◈题⟧` 包住"题"字，其后的 `〖聯〗` 就落在动作标记内，可能嵌套。

### 6.3 留下的启发

> **不要因为"那边有"就移植。**
> 移植前必须问："这个类型在我的文体里对应什么实体？"
> 答不上来，就不该移植。

**这回答了"本项目为什么没有动词层"——不是忘了，是想清楚了。**

## 七、L3：两层校验的思想

### 7.1 什么是"两层"

| 层 | 检查什么 | 本项目实现 |
|---|---|---|
| **格式层** | 标记是否合法、原文是否被改动 | `lint_text_integrity.py` 5 项 |
| **领域层** | 内容是否符合文体的形式约束 | 上下联等长、末字不同 |

### 7.2 为什么两层都必要

**格式层通过，领域层可能惨败。**

本项目的真实例子：

```
格式校验：5/5 全通过 ✅
等长率：  1.4%           ❌
```

原因：下联末尾的 `。` 不属于联句，但它是原文的一部分——
**格式层无法判断"这个句号该不该算进联句"**，只有领域知识能判断。

### 7.3 启发

> **格式校验证明"没搞坏"，领域校验证明"搞对了"。**
> 两者缺一不可。

## 八、L3：反演校验（strip_markup）

### 8.1 定义

```
原文  ──加标记──▶  标注文
                    │
                    ▼ 去掉所有标记
                 必须逐字等于原文
```

### 8.2 本项目的实现

```python
def strip_markup(text):
    # 去掉 〖TYPE 内容〗 → 内容
    # 去掉 〖TYPE 显示|规范〗 → 显示
    # 去掉 〖聯〗 等零宽标记
    # 去掉 █ ▓ 等渲染符号
    return stripped
```

### 8.3 为什么这是"铁律"

只要反演成立，就**保证了没有增删改原文**。
这比"人工抽查"可靠得多。

**本项目实测**：2,289/2,289 段通过。

## 十、十句最该记住的继承

如果只记十条，记这十条：

1. **`〖TYPE 内容〗` 优于 XML** —— 人要先能读。
2. **三个符号集合不重叠** —— 同一定界符只做一件事。
3. **只加标记，不改原文** —— 反演校验是铁律。
4. **先结构后实体** —— 顺序颠倒必返工。
5. **Purple Numbers 不随插入而变** —— 地址必须稳定。
6. **能用规则绝不用模型** —— 可审计优先。
7. **元数据宁可缺，不可错** —— 精度 > 召回。
8. **不要因为"那边有"就移植** —— 问它在本文体对应什么。
9. **格式层 + 领域层，两层都要** —— 前者证明没搞坏，后者证明搞对了。
10. **完成不等于正确** —— 用统计分布发现系统性错误。
