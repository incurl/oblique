# SKILL 05: 形制校验

> **核心理念**：**只检查格式的校验器，会对系统性数据错误完全沉默。**
> 格式正确 ≠ 数据正确。必须再加一层"用文体自身的规训校验"。

## 二、第一层：格式校验（五项）

### 2.1 核心函数：模拟"擦掉标记"

```python
def strip_markup(text):
    """去掉所有标注符号，保留原文字符。"""
    text = text.replace("〖聯〗", "").replace("〖對〗", "")
    # 〖TYPE 显示名|规范名〗 → 显示名
    text = re.sub(r"〖([@=;%&◆^~•!?+{:[_#$])([^〗|]*)(?:\|[^〗]*)?〗", r"\2", text)
    text = re.sub(r"〘(.)([^〙]*)〙", r"\2", text)   # 〘※成语〙 → 成语
    text = re.sub(r"⟦(.)([^⟧]*)⟧", r"\2", text)   # ⟦◈伐⟧ → 伐
    return text
```

**这是整个校验的核心**：它模拟"读者把标记擦掉"。
如果擦掉后与原文不同，说明标记**改变了内容**。

### 2.2 五项检查

| # | 检查 | 实现要点 |
|---|---|---|
| 1 | **原文完整性** | 逐行 `strip_markup` 后与源文件比对 |
| 2 | **括号配对** | `text.count("〖")==text.count("〗")` 等三对 |
| 3 | **无嵌套** | 正则 `〖[^〗]*[〖〘⟦]` 等 |
| 4 | **无半角引号** | U+0022 / U+0027 计数与源文件对比 |
| 5 | **类型白名单** | 只允许 18 类 + `聯`/`對` |

### 2.3 逐行比对的口径

```python
def source_content_lines(lines):
    """源文件中应出现在正文里的行（与 [id] 行一一对应）。"""
    out = []
    for no in range(80, 89):          # 作者简介
        out.append((no, lines[no-1]))
    for idx in range(88, len(lines)):  # 正文
        no, raw = idx+1, lines[idx]
        if no in SKIP_LINES: continue        # 目录/书名行
        if no in HEADINGS: continue          # 标题行
        if raw.startswith("\t"): out.append((no, raw)); continue
        if raw.endswith(("。","！","？","；","：")) or len(raw) >= 24:
            out.append((no, raw))            # 续行
    return out
```

**要点**：**跳过标题行**（标题是元数据，不是正文），
但**收录续行**（续行是正文的一部分）。

## 三、第二层：领域校验（四项）

### 3.1 为什么需要第二层

本项目联语数据**通过了全部 5 项格式校验**，但**数据是错的**：

```
上下联等长: 41/3021 = 1.4%      ← 楹联最基本的形制是等字数
```

**格式层面完全正确**——原文一字未改，标记完全合法，
只是**语义切分错了**（下联末尾的句号被算进正文）。

### 3.2 四项领域检查

| 检查 | 判据 | 当前值 |
|---|---|---:|
| 上下联等长 | `len(upper) == len(lower)` | **100%** |
| 末字不同 | 上下联末字不重复 | 99.93% |
| 联语非空 | 上下联各 ≥ 2 字 | 100% |
| 类型可识别 | 落在 11 类内 | 100% |

### 3.3 用文体自身的规训

楹联的硬约束（**可自动检查的**）：

| 规训 | 内容 | 本项目 |
|---|---|---|
| **字数相等** | 上下联字数必须相同 | ✅ 100% |
| **末字不同** | 上下联末字不可重复（"合掌"） | ✅ 99.93% |
| 词性相对 | 名对名、动对动 | ⚠️ 需分词，未做 |
| 结构相应 | 短语结构平行 | ⚠️ 需句法，未做 |
| 平仄相配 | 上仄下平 | ❌ 需韵书，见 §5 |

**能自动检查的只有前两项**，但这两项已经足够抓出系统性错误。

## 四、两次真实的数据事故

### 4.1 事故一：末尾句读（1.4%）

**现象**：等长率 1.4%。

**诊断**：

```
上：'新年纳余庆'        6 字
下：'嘉节号长春。'      7 字 ← 含句号
```

**根因**：原文写作 `"上联；下联。"`，句号属于**引文**，不属于**下联**。

**修复**：`_strip_line_ending()`。

**效果**：1.4% → 93.7%。

### 4.2 事故二：出处冠名（93.7% → 99.34%）

剥离句号后仍有 189 副不等长。逐一查看：

```
上(7)  紫阁丹楼纷照耀
下(9)  王勃桃溪柳陌好经过     ← "王勃"是出处，不是联句
```

**修复**：`_detect_source_prefix()`（四个位置，见 SKILL_04 §6）。

**效果**：93.7% → 99.1% → 99.34%。

### 4.3 两次事故的共同结构

| | 事故一 | 事故二 |
|---|---|---|
| 表面 | 格式全通过 | 格式全通过 |
| 发现方式 | **领域校验** | **领域校验** |
| 根因 | 标点归属 | 出处归属 |
| 教训 | 格式正确 ≠ 数据正确 | **领域校验往往需要多轮** |

> **第一轮的"基本对"往往只是"第一层对"。**
> 第一轮剥句号，第二轮才发现出处冠名，第三轮才发现编者标记。

## 五、一个不做的检查：平仄

楹联还有"上仄下平"，本项目**未实现**，理由：

1. 需要《平水韵》《中华新韵》完整韵书，超出工程范围
2. 平仄检查假阳性高——集句联常有意拗句，巧对更不拘平仄
3. **数据已可支持平仄研究**：有 `upper`/`lower` 两列，
   研究者自行接韵书即可

**这是一条重要的分工原则**：

> **标注层负责忠实提取文本中确定存在的信息；
> 分析层负责引入外部知识（韵书、格律）做判断。**

标注层一旦引入韵书，就会出现"为了平仄而改动切分"的压力，
进而威胁"只加不改"原则的纯度。

## 六、校验器自身的陷阱

**校验器也是代码，也会骗人。**

第一次实现时报了两个假阳性：

```
未知标记类型：〖T
引入半角引号：源文件 0 个，标注文件 4956 个
```

| 假阳性 | 来源 |
|---|---|
| `〖T` | 规范文档里的示例文字 `〖TYPE 内容〗` 被当正文扫描 |
| 4956 个半角引号 | HTML 属性 `title="人名"` 被误判成正文 |

**修复**：校验器只检查**带 `[id]` 前缀的正文行**：

```python
def tagged_content_lines(text):
    out = []
    for lineno, line in enumerate(text.splitlines(), 1):
        m = re.match(r"^\[([0-9.]+)\] (.*)$", line)
        if m:
            out.append((lineno, strip_markup(m.group(2)), m.group(2)))
    return out
```

> **教训**：一个刚愎自用的校验器，会让人误以为数据有问题，
> 进而去"修"本来正确的数据——这是最坏的情况。
>
> 校验器必须：① 只检查真正该检查的范围；
> ② 报出行号/原文/标注文本供人判断；③ 报错时**先怀疑自己**。

## 七、禁止事项与推荐做法

### 7.1 禁止

❌ **只跑格式校验就宣布完成** —— 会对系统性错误完全沉默。

❌ **用布尔标记代替事实** —— 如 `balanced: false`，
混淆"切分错了"与"这副联本就不等长"（已删除该字段）。

❌ **校验器全文件扫描** —— 会把文档示例、HTML 属性当正文。

### 7.2 推荐

✅ **两层校验都必须通过才提交**。

✅ **报错要给行号与原文** —— 便于人工判断。

✅ **把校验写进标准流程** —— 生成 → 校验 → 渲染，三步固定顺序。

✅ **领域阈值写进文档** —— 等长率 < 90% 就该怀疑数据。

## 十、FAQ

**Q：等长率为什么不是 100%？**
A：剩下 20 副（0.66%）**真的不等长**——长联（22 vs 52 字）、
带散文的巧对（"钱唐有两进士：一林和靖，居孤山"）。
强行凑齐就是改数据。**如实保留，由 `upper_len`/`lower_len` 陈述事实。**

**Q：为什么删掉了 `balanced` 字段？**
A：它混淆了"切分错了"与"这副联本就不等长"两种情况。
剥离干净后，剩下的确实本来不等长，标记已无信息量。
**一个字段如果不能区分它宣称要区分的两种情况，就该删掉。**

**Q：校验失败但我觉得数据是对的怎么办？**
A：先怀疑校验器。检查它是不是扫描了不该扫的行。
本项目已踩过这个坑（§6）。
