# SKILL 03: 实体标注

> **核心理念**：**只加标记，不改原文。**
> 标注文件的判据不是"看起来标得对"，而是"去掉标记后能否逐字还原"。

---

## 一、任务定义

### 1.1 何时使用

- 要在原文中标出人名、地名、官职等专名
- 要新增一个实体类型
- 实体边界有争议（"关帝庙"标地名还是神祇？）

### 1.2 输入与产出

| | 内容 |
|---|---|
| 输入 | 已编号的正文（SKILL_02） |
| 产出 | 带 `〖〗` 标记的正文 + `entities.json` |
| 前置 | [SKILL_02](SKILL_02_结构切分与段落编号.md) |
| 后继 | [SKILL_04](SKILL_04_联语识别.md)、[SKILL_06](SKILL_06_语料构建与渲染.md) |

### 1.3 成功标准

- [ ] 去标记后与源文件逐字相同（SKILL_05 硬性校验）
- [ ] 无嵌套标记
- [ ] 所有标记类型在白名单内

**当前基线**：13,135 处标注 / 2,979 个规范名。

### 2.1 选类型的两个维度

**封闭 vs 开放**

| 封闭（可枚举） | 开放（不可枚举） |
|---|---|
| 朝代（30）、年号（500）、官职（800） | 人名（数万）、地名（数千） |
| 词表驱动，准确率接近 100% | 需语义判断，约 95% |

**正交吗？**

> 同一个词在任何上下文中都应明确属于唯一类型。

本项目真实遇到的歧义：

| 词 | 歧义 | 解法 |
|---|---|---|
| `文昌` | 神祇（文昌帝君）/ 建筑（文昌宫） | 神祇收 `文昌`；地名收 `文昌宫`（长词优先） |
| `关帝庙` | 地名 / 神祇 | 地名整体标注，不再拆出 `关帝` |
| `万安` | 县名 / 殿名 / 人名 | **不收**（见 SKILL_03b 黑名单） |

## 三、边界三原则

### 3.1 最小完整单位

```python
✅ 〖@梁章钜〗              # 完整人名
✅ 〖;观察〗〖@成宪〗       # 官职与人名分开
❌ 〖@梁章〕                # 拆了完整人名
❌ 〖;观察成宪〗            # 官职与人名混淆
```

### 3.2 不包含非实体成分

```python
✅ 〖@梁章钜〗，〖@阮元〗
✅ 伐〖◆后蜀〗
❌ 〖@梁章钜，〗            # 含标点
❌ 〖@梁章钜〗撰联          # 动词应在标记外
```

### 3.3 典籍：书名号留在标记外

原文写 `《春秋》`，两种做法：

| 做法 | 例 | 问题 |
|---|---|---|
| 标整个书名号 | `〖{《春秋》}〗` | 违反原则 2（含标点） |
| **标内部、保留括号** | `《〖{春秋〗》` | ✅ 边界干净，可还原 |

**实现**：正则只匹配 `《` 与 `》` 之间的内容。

```python
BOOK_RE = re.compile(r"《([^》\n]{1,40})》")   # 只取 group(1) 作标记内容
```

### 4.2 贪心选择算法

```python
def select_candidates(cands):
    # ① 起点靠前 ② 同起点取长词 ③ 同长取高优先级
    cands.sort(key=lambda c: (c.start, -(c.end - c.start), -c.priority))
    selected, cursor = [], 0
    for c in cands:
        if c.start < cursor:      # 与已选区间重叠 → 丢弃
            continue
        selected.append(c)
        cursor = c.end
    return selected
```

**三层排序键的含义**：

1. 起点优先 —— 扫描顺序稳定
2. **长词优先** —— `〖=关帝庙〗`（3 字）先于 `〖?关帝〗`（2 字）
3. 优先级兜底 —— 同起点同长度时，类型优先级高者胜

### 4.3 拍平的副作用（必须知道）

`〖=关帝庙〗` 吸收了内部的 `关帝`，
于是**神祇"关帝"在这条记录里不可检索**。

这是"最小完整单位"与"完整覆盖"的固有张力。
处理方式：**接受损失，但在统计中可见**——
`entities.json` 里 `关帝` 计数是 11（独立标注数），
不是"文中提到关帝的总次数"。

## 五、禁止事项与推荐做法

### 5.1 禁止

❌ **嵌套标记** —— `〖@⟦◈破⟧奴〗`、`〖#〖@天子〗〗` 一律禁止。

❌ **修改原文任何字符** —— 包括全角/半角转换、增删标点。

❌ **把动词包进实体** —— "伐""撰""题"应在标记之外。

❌ **标点进实体边界** —— `〖@刘邦，〗`。

### 5.2 推荐

✅ **长词优先** —— 让 `关帝庙` 压住 `关帝`。

✅ **典籍优先级最高** —— 书名内部不再标任何实体。

✅ **词表集中管理** —— 全部在 `scripts/yinglian_dict.py`（见 SKILL_03b）。

✅ **每加一类先做正交性检验** —— 问"这个词会不会同时属于两类"。

## 八、FAQ

**Q：`集句`、`挽联` 算名物还是制度？**
A：归 `^名物`（与"楹联""桃符"同类）。
而"这副联是挽联"这类判断**不进实体层**，
进 `couplets.json` 的 `type` 字段（SKILL_04）——分类进元数据，不进正文。

**Q：`进士`、`举人` 是官职还是身份？**
A：`#身份`。它们是科举功名，不是朝廷任命的实职。
`;官职` 只收有品级的职位。

**Q：能自动到什么程度？**
A：封闭类接近 100%；开放类取决于词表覆盖，本项目约 85–90%。
**不追求全自动，追求"可审计"**。
