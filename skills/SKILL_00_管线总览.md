# SKILL 00: 管线总览 —— 从纯文本到可检索语料

> 本文件只描述**工序顺序与依赖关系**，具体方法见各阶段 SKILL。

---

## 一、一句话概括

**把一部 2,588 行的清代联话纯文本，变成带永久编号、18 类实体标注、
3,020 副联语语料的可检索文本——且保证原文一字未改。**

---

## 二、七阶段管线

```
楹联丛话全编.txt（2,588 行 / 332,547 字，只读）
    │
    ▼ 01 底本分层与符号原则
    │   分清「原文 / 整理者附注 / 电子本目录」
    │   确定全套标记符号（18 类 + 聯 + 三类括号）
    │   → 产出：符号约定（写进 SPEC）
    │
    ▼ 02 结构切分与段落编号
    │   解析 书 → 卷 → 门类 → 条目 → 段落
    │   分配 Purple Numbers [1.3.1]，生成锚点 #pn-1.3.1
    │   → 产出：structure.json
    │
    ▼ 03 实体标注
    │   词典 + 正则，匹配 18 类名词实体
    │   优先级拍平，内联消歧 〖@显示名|规范名〗
    │   → 产出：带 〖〗 标记的正文
    │
    ▼ 04 联语识别
    │   〖聯〗 前置标记（引号联）+ ::: 联 块（无引号巧对）
    │   剥离出处冠名与编者标记，切分 upper/lower
    │   → 产出：couplets.json
    │
    ▼ 05 形制校验（两层）
    │   格式层：原文完整性 / 括号配对 / 无嵌套 / 引号 / 类型白名单
    │   领域层：上下联等长 / 末字不同 / 非空 / 类型可识别
    │   → 产出：可证伪的质量断言
    │
    ▼ 06 语料构建与渲染
    │   三个 JSON 索引 + HTML 静态预览
    │   → 产出：index.html
    │
    ▼ 07 质量反思（贯穿 03–05）
        多轮迭代，把误判固化为规律（Y1–Y10）
```

**关键顺序约束**：**02 必须先于 03/04 完成**。
段落边界一旦返工，全部编号与标注作废。

## 三、脚本分工

| 脚本 | 阶段 | 职责 | 是否可直接运行 |
|---|---|---|---|
| `scripts/yinglian_dict.py` | 01/03 | 全部词表（人名、地名、官职、联语术语、出处名…） | 否（被导入） |
| `scripts/yinglian_lib.py` | 02/03/04 | 解析器 + 实体匹配 + 联语识别 + 标注渲染 | 否（被导入） |
| `scripts/annotate_yinglian.py` | 02–04/06 | 编排全流程，产出 Markdown + 三个 JSON | ✅ |
| `scripts/lint_text_integrity.py` | 05 | 文本完整性 / 嵌套 / 引号 / 类型校验 | ✅ |
| `scripts/render_yinglian.py` | 06 | 生成静态 HTML 预览 | ✅ |
| `scripts/export_tiddlywiki.py` | 06 | 导出 TiddlyWiki（条目为 tiddler、实体为 tag） | ✅ |
| `scripts/verify_tiddlywiki.py` | 06 | 用独立数据源交叉校验导出结果 | ✅ |

**标准执行顺序**：

```bash
python3 scripts/annotate_yinglian.py     # 生成
python3 scripts/lint_text_integrity.py   # 校验（不通过就不要提交）
python3 scripts/render_yinglian.py       # 渲染
python3 scripts/export_tiddlywiki.py     # 导出 TiddlyWiki
python3 scripts/verify_tiddlywiki.py     # 校验导出（不通过就不要提交）
```

**设计原则**：`annotate_yinglian.py` 是**纯函数式**的——
同样输入必然产生同样输出。这使校验可复现、Git diff 只反映词表变化。

## 四、数据流转

```
                    ┌─────────────────────────────┐
                    │ 楹联丛话全编.txt（只读）      │
                    └──────────┬──────────────────┘
                               │ parse_document()
                               ▼
                    ┌─────────────────────────────┐
                    │ Document 树                  │
                    │  Book → Volume → Section     │
                    │       → Entry → Paragraph    │
                    └──────────┬──────────────────┘
                               │
              ┌────────────────┼────────────────┐
              ▼                ▼                ▼
      annotate_text()   find_couplets()   build_structure()
              │                │                │
              ▼                ▼                ▼
    ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
    │ 带标记正文    │  │ 联语记录      │  │ 结构树        │
    └──────┬───────┘  └──────┬───────┘  └──────┬───────┘
           │                 │                 │
           ▼                 ▼                 ▼
     .tagged.md      couplets.json     structure.json
           │                 │                 │
           └────────┬────────┘                 │
                    ▼                          │
             entities.json  ◄──────────────────┘
                    │
        ┌────────────┴────────────┐
        ▼                         ▼
  index.html（渲染）      tiddlywiki/（导出）
                            条目=tiddler，实体=tag
```

**唯一事实源是 `.tagged.md`**。
三个 JSON 全部由它派生，因此不可能与正文不一致。

## 六、与"通用古籍标注"的差异

本项目不是《史记》那类史书，而是**联话**。三个根本差异：

| 维度 | 史书 | 联话（本项目） |
|---|---|---|
| 核心对象 | 人物、事件、纪年 | **联语**（成对韵文） |
| 结构特征 | 叙事连贯 | 大量引号引用，实体被引文包裹 |
| 形式约束 | 无 | **严格**：等字数、末字异、上仄下平 |

因此：**通用实体层只覆盖一半工作量**，
另一半（联语边界、出处冠名、形制校验）是本书特有的，见 SKILL_04/05。
