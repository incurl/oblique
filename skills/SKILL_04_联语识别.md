# SKILL 04: 联语识别

> **核心理念**：**联语标记是"结构标记"，不是"实体标记"。**
> 它标记的是一段文字的**角色**（这是对联），而不是其中的**成分**（里面有人名）。

---

## 一、任务定义

### 1.1 何时使用

- 文本以"联"为核心对象（联话、对联集）
- 需要把"上联；下联"切分开
- 需要判断一副联的类型与作者

### 1.2 输入与产出

| | 内容 |
|---|---|
| 输入 | 已标注实体的正文（SKILL_03） |
| 产出 | `〖聯〗` 标记 + `: : : 联` 块 + `couplets.json` |
| 前置 | [SKILL_02](SKILL_02_结构切分与段落编号.md)（段落单元） |
| 后继 | [SKILL_05](SKILL_05_形制校验.md)（等长校验） |

### 1.3 成功标准

- [ ] 带引号的联语被标 `〖聯〗`
- [ ] 无引号的巧对被包 `::: 联` 块
- [ ] 上下联切分正确，出处冠名已剥离
- [ ] 类型、作者、地点字段有明确的可靠性分级

**当前基线**：3,016 副（100% 上下联等长），出处冠名 171 副，作者线索 91 副。

## 二、为什么 18 类实体不够

联话的每段几乎都长这样：

> 京师陶然亭，康熙年间水部郎江藻所建……联云："慧眼光中，开半亩红莲碧沼；烟花象外，坐一堂白月清风。"

有地名（京师、陶然亭）、人名（江藻）、官职（水部郎），
**也有一副完整的联语**。

18 类实体能覆盖前者，对后者无能为力——因为**联语的边界是句子级的，不是词级的**。

## 三、标记的形状：三次否决

### 3.1 方案 A：用实体层包裹 ❌

```markdown
〖聯 慧眼光中，开半亩红莲碧沼；烟花象外，坐一堂白月清风〗
```

**失败原因**：联内若有人名就无法再标。

```markdown
〖聯 林少穆题：山月不随江水去〗     ← 里面的"林少穆"标不了
```

违反"不嵌套"原则，也牺牲了联内实体的可检索性。

### 3.2 方案 B：用动词层 `⟦⟧` ❌

```markdown
⟦◈联⟦@林少穆⟧题：山月不随江水去⟧
```

**失败原因**：`⟦⟧` 是为单字动词设计的（伐/攻/杀/诛/立/封），
联语是复合结构；且同样造成嵌套。

### 3.3 方案 C：包裹引号 ❌

```markdown
〖聯〗“〖@林少穆〗题：山月不随江水去”
```

**失败原因**：标记的是"引号"而不是"联"，而引号内可能只是普通引述。

### 3.4 方案 D：前置标记 ✅

```markdown
……联云：〖聯〗“慧眼光中，开半亩红莲碧沼；烟花象外，坐一堂白月清风。”
```

`〖聯〗` 是**零宽前置提示符**：

| 特性 | 说明 |
|---|---|
| 不包裹正文 | 联内可继续标 `〖@林少穆〗`、`〖=焦山〗` |
| 不改变原文 | 去掉它，引号内外一字不动 |
| 可与任何标记共存 | 不产生嵌套 |
| 位置明确 | 紧贴引号，表示"其后引号内是联" |

**这是设计，不是妥协。** 它与实体层是正交的两个维度：

```
实体层：这段文字里有哪些成分？   → 〖@林少穆〗〖=焦山〗
联语层：这段文字整体是什么？      → 〖聯〗
```

## 四、两条识别路径

### 4.1 有引号 → 行内标记

绝大多数联语被引号包裹，用 `〖聯〗`。

**识别条件**（需同时满足）：

| # | 条件 | 依据 |
|---|---|---|
| 1 | 含全角分号 `；` | 对联的基本分隔 |
| 2 | 长度 5–260 字 | 太短不是联，太长是整段叙述 |
| 3 | 除末尾外不含 `。` | 联内不应有句号 |
| 4 | `；` 不超过 4 个 | 多句是"联语组" |
| 5 | `，` 不超过 12 个 | 防长篇引述被误判 |
| 6 | 上下联长度比 0.3–3.3 | 明显失衡的不是联 |
| 7 | **不以叙述词开头** | "按""此""余""今""盖" = 叙述 |

第 7 条尤其重要：联话里大量"按《某书》载：……"，
引号内是**引文**而非**联语**。

```python
COUPLET_BAD_PREFIX = (
    "按", "此", "余", "今", "又", "故", "盖", "然", "而", "且", "若", "如",
    "所谓", "云", "曰", "或者", "或", "有", "无", "其", "之", "以", "为",
)
```

### 4.2 无引号 → 块级标记

《巧对录》《巧对续录》收的是**对语**，不是挂在柱子上的联——
原文中**没有引号**，以分号排比直接出现：

> 地媪；天公。山骨；泉心；雌霓；雄风。湖目；溪心。笠泽；弁山。

用 Fenced Div 包住整段：

```markdown
::: 联
[5.1.1.1] 地媪；天公。山骨；泉心；雌霓；雄风。……
:::
```

**判据**：段落中 `；` ≥ 2，`。` ≤ `；`+2，平均分句长度 ≤ 26 字。

### 4.3 为什么分两条路径

| 有起止符号（引号） | 整段即语义单元 |
|---|---|
| 行内标记 `〖聯〗` | 块级标记 `::: 联` |

**全项目**：`::: 联` 块 89 个，`〖聯〗` 行内标记 3,020 处。

## 五、切分：上下联与三样"杂质"

`quote.split("；", 1)` 看似足够，实则要剥三样东西：

```
原文：〖聯〗“新年纳余庆；嘉节号长春。”
                    ↓ ①剥离末尾句读
       上：新年纳余庆     下：嘉节号长春
```

| 杂质 | 例 | 处理 | 字段 |
|---|---|---|---|
| **① 末尾句读** | 下联末尾的 `。` | 剥离 | — |
| **② 出处冠名** | `王勃桃溪柳陌好经过` 的"王勃" | 剥离 | `lower_source` |
| **③ 编者标记** | `见上`、`一作` | 剥离 | `editorial_markers` |

**三者都不属于联句本身。** 原文完整保留在 `text` 字段。

### 5.1 为什么句读必须剥离

若不剥，下联凭空多一字，**等长率会从 99% 跌到 1.4%**
（这是本项目最贵的教训，详见 [SKILL_05](SKILL_05_形制校验.md)）。

```python
def _strip_line_ending(line):
    return line.rstrip("。！？!?，、；; ")
```

## 六、出处冠名：集句联的结构

《楹联丛话》大量收录**集句联**——上下联各集前人诗句。
这类联把出处与联句并置，**出处不是联句的一部分**。

### 6.1 四种位置

| 位置 | 例 | 剥离后 |
|---|---|---|
| **下联前置** | `…；王勃桃溪柳陌好经过` | 上 7 / 下 7 |
| **下联后置** | `…；太白、右丞` | 上 5 / 下 5 |
| **下联后置（连写）** | `…；落笔超群英少陵、太白` | 上 5 / 下 5 |
| **上联前置/后置** | `上：…永享年寿孔宙；下：应期作弼，入参文昌` | 上 9 / 下 9 |

**第四条最容易漏**：汉碑集句的出处常冠在上联。

### 6.2 三种形态

1. **诗人名** —— 杜甫、王勃、刘长卿、綦母潜
2. **「X句」缩写** —— 苏句、山谷句、荆公句
3. **文献题名** —— 高后碑、谢庄武帝册、唐刘待价令狐仁政碑

### 6.3 判定：形制自证，不靠词典猜

**核心方法**：尝试剥离任一联的首 k 字或末 k 字，
**若剥离后两联等长**，且该段形似出处，则认定为冠名。

```python
MAX_SOURCE_PREFIX = 10   # 八字联的出处可达 9 字（唐刘待价令狐仁政碑）

def _detect_source_prefix(upper, lower):
    # ① 下联前置
    for k in range(min(MAX_SOURCE_PREFIX, len(lower)-2), 1, -1):
        if len(lower)-k == len(upper) and _looks_like_source(lower[:k]):
            return lower[:k], upper, lower[k:]
    # ② 下联后置（…A、B）
    for cut in range(len(lower)-2, 2, -1):
        tail, rest = lower[cut:], lower[:cut]
        if "、" in tail and len(rest) == len(upper):
            pair = _extract_name_pair(tail)
            if pair in _KNOWN_SOURCE_PAIRS:
                return pair, upper, rest
    # ③ 上联前置/后置（同理）
    ...
    return "", upper, lower
```

**为什么用形制自证而不是纯词典匹配**：

> 纯词典要枚举"诗人名/字号/文献题名"三种形态，必然遗漏；
> 形制自证只需一条规则——**等长**——词典只用于"确认"剥离出的片段像出处。
>
> 这也符合联话自身的逻辑：**出处的存在与否，由联语的等字数形制来证明。**

### 6.4 形似出处的判据

```python
def _looks_like_source(prefix):
    if prefix in QUOTE_SOURCE_NAMES:  return True      # 已知诗人名
    if prefix in QUOTE_SOURCE_WORKS:  return True      # 已知文献名
    if prefix.endswith("句") and len(prefix) <= 5:  return True   # 苏句
    if len(prefix) >= 3 and prefix[-1] in "句碑赋传册集记序颂诏书篇卷品话录志谱表经解引":
        return True                                     # 高后碑、大隐赋
    if "、" in prefix:                                  # 少陵、太白
        return all(part in KNOWN for part in prefix.split("、"))
    return False
```

## 七、编者标记：「见上」「一作」

第三类杂质是**校勘层**，不是原文。

| 标记 | 含义 | 例 | 处理 |
|---|---|---|---|
| `见上` | 见上联（指前一条已引的上联） | `含和履仁见上，永享年寿孔宙` | 删除 |
| `一作` | 一本作（异文，后接另一版本） | `看儿曹整顿一作旋转乾坤` | 删除 |
| `又作` | 同上 | | 删除 |

```python
EDITORIAL_MARKERS = ("见上", "一作", "又作")

def _strip_editorial_markers(line):
    removed = []
    for m in EDITORIAL_MARKERS:
        if m in line:
            removed.append(m)
            line = line.replace(m, "")
    return line, removed
```

**被剥离的标记记入 `editorial_markers` 字段，原文完整保留在 `text`。**

### 7.1 ⚠️「一曰」不是编者标记

```
受天地之中，以生一曰水；有功德于民，则祀谓之神。
```

这里的 `一曰` 是**五行名目的正文**（一曰水、二曰火……），
误剔会破坏联句。**修订中曾误加，已回退。**

> **判据：看它是否参与语义。** "一作"后接的是"另一个版本"，
> "一曰"后接的是"本句内容的一部分"。

## 八、类型推断

联语的类型（挽联/寿联/…）**不写在原文里，必须推断**。

依据：**联语前 60 字 + 所属门类标题**

```python
def _couplet_type(text, start, section=""):
    ctx = section + text[max(0, start-60):start]
    if "挽" in ctx: return "挽联"
    if "寿" in ctx or "祝" in ctx: return "寿联"
    if "贺" in ctx or "喜" in ctx: return "贺联"
    if "春" in ctx or "桃符" in ctx: return "春联"
    if "集" in ctx and ("句" in ctx or "字" in ctx): return "集句"
    if any(k in ctx for k in "庙祠寺观"): return "庙联"
    if "会馆" in ctx: return "会馆联"
    if "门" in ctx: return "门联"
    if "堂" in ctx: return "堂联"
    if "巧对" in ctx or "对语" in ctx: return "巧对"
    return "联语"          # 兜底类
```

**这是诚实标注为"启发式"的字段。** 它无法分辨同时是庙联和贺联的联，
也无法分辨"堂联"与"厅联"（后者归入联语兜底类，占 19%）。

## 九、作者线索：一个必须克制的字段

作者是研究者最想要的元数据，也是最容易错的。

### 9.1 初版怎么错的

初版取"联语前 90 字内最后一个人名"，结果：

| 误判 | 上下文 | 真相 |
|---|---|---|
| 朱子 | "又《朱子全集》卷后所附载联语尚多" | 书名里的 |
| 庄子 | "庄子七言云：'我书意造本无法'" | 集句，被集的诗人 |
| 王勃 | "王勃东屋山池赋琴号珠柱" | 引文，非作者 |
| 紫阳 | "时石掌教苏州之紫阳书院" | 书院名 |

**根因**："人名 + 某动词" ≠ "人名是作者"。引文、书名、院名都会命中。

### 9.2 高精度模式

```python
AUTHOR_VERB_RE = re.compile(
    r"^[^。；\n]{0,8}(?:撰|题|手题|自题|敬题|谨撰|书联|书楹|书此|"
    r"作联|作楹|集句|集字)(?=[联楹此一云曰：，、于]|$)"
)
```

只认"**人名紧接 撰/题/书联/作联/集句**"，且其后紧跟"联/楹/此/一云/曰"。

再加两条过滤：

- 短名若被更长人名包含（"紫阳"在"朱紫阳"中）→ 丢弃
- 人名后紧跟"书院/宫/祠/庙/楼/亭"等后缀 → 丢弃

### 9.3 三档可靠性

| 字段 | 做法 | 覆盖 | 可靠性 |
|---|---|---:|---|
| `author` | 人名 + 撰/题/书联（高精度） | 91（3.0%） | **高** |
| `author_near` | 联前最近人名 | 更多 | **低**，仅线索 |
| `context` | 联前 100 字原文 | 全部 | **高**，供人工复核 |

```json
{
  "author": "孟昶",
  "author_near": "孟昶",
  "context": "……自命笔云："
}
```

**宁可少标，不可错标。**
覆盖率从 255 降到 91（8.4% → 3.0%），但**准确率从"不可用"到"可用"**。

> 存储 `context` 是关键决定：它让研究者不必打开源文件
> 就能判断元数据对不对，也给不确定字段一个申诉渠道。

## 十、禁止事项与推荐做法

### 10.1 禁止

❌ **包裹式联语标记** —— 会与内部实体标记冲突，造成嵌套。

❌ **把出处冠名当联句正文** —— 会让上下联凭空不等长。

❌ **把「一曰」当编者标记** —— 它是五行名目的正文（已踩过）。

❌ **用"最近人名"当作者** —— 误判率过高，见 §9.1。

### 10.2 推荐

✅ **前置零宽标记** —— 不破坏内部标注。

✅ **形制自证判出处** —— 比纯词典枚举更稳。

✅ **标记剥离但原文保留** —— `text` 存原文，剥离结果进独立字段。

✅ **可靠性分级写进字段名** —— `author` vs `author_near` 一眼可辨。

## 十三、FAQ

**Q：为什么不用深度学习做对联识别？**
A：联语的判据是**形式特征**（含分号、等长、无句号），
规则即可覆盖且可解释。上模型反而引入不可控错误。

**Q：`type` 分错要紧吗？**
A：比实体标错轻。它是启发式字段，已在文档中声明。
但若"联语"兜底类占比超过 25%，说明规则需要补。

**Q：出处冠名剥离后，原文信息会丢吗？**
A：不会。`text` 字段保留引号内完整原文（含出处与标记），
只是 `upper`/`lower` 是"净联句"。

**Q：一副联既是庙联又是寿联怎么办？**
A：当前取第一个匹配的关键词，结果不稳定。
这是已知缺陷，见 [SKILL_07](SKILL_07_质量反思与规律库.md)。
