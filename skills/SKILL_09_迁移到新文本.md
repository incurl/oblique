# SKILL 09: 迁移到新文本

> **核心理念**：**框架可继承，细节必须重做。**
> 直接照搬是浪费，重新发明也是浪费——难的是判断哪个是哪个。

---

## 一、任务定义

### 1.1 何时使用

- 要把这套方法用到另一部书
- 要评估"这个框架适不适合我的文本"

### 1.2 迁移的三问

```
① 我的文本的核心对象是什么？        → 决定是否需要新的标记层
② 它有什么形式约束？                → 决定领域校验做什么
③ 它与已有文体差在哪？              → 决定哪些规则会失效
```

## 二、可继承清单（约 70%）

这些是**与文体无关**的工程骨架，可以直接搬。

### 2.1 结构与编号

| 可继承 | 说明 | 需要改的 |
|---|---|---|
| 五级树（书/卷/门类/条目/段落） | 层级模型通用 | 具体标题行号 |
| Purple Numbers 编号规则 | 位置决定编号 | 层级深度 |
| 续行合并机制 | 排版断行处理 | 长度阈值（本项目 24 字） |
| 目录由结构树生成 | 避免手工维护 | — |

### 2.2 符号与语法

| 可继承 | 说明 |
|---|---|
| `〖TYPE 内容〗` 语法 | 通用 |
| 18 类实体定义 | 通用（可裁剪） |
| `〖TYPE 显示名\|规范名〗` 消歧 | 通用 |
| 三个符号集合分离原则 | 通用 |
| "只加标记不改原文" | **铁律，不可改** |

### 2.3 工程质量

| 可继承 | 说明 |
|---|---|
| 两层校验（格式 + 领域） | 通用框架 |
| `strip_markup()` 反演校验 | 通用 |
| Markdown + JSON 双轨制 | 通用 |
| 唯一事实源原则 | 通用 |
| 规律库机制 | 通用 |
| 多轮反思节奏 | 通用 |

### 2.4 元方法

| 可继承 | 说明 |
|---|---|
| 先结构后实体 | 顺序不可颠倒 |
| 能用规则绝不用模型 | 可审计优先 |
| 元数据宁可缺不可错 | 精度优先于覆盖率 |
| 完成不等于正确 | 用统计分布发现问题 |

## 三、必须改造清单

### 3.1 识别信号

**每种书的层级靠什么区分？**

| 书型 | 层级信号 | 本项目 |
|---|---|---|
| 联话 | 制表符缩进 + 短行标题 | ✅ |
| 诗话 | 可能以"卷"为主，条目无标题 | 需改 |
| 方志 | 大量表格/条目化 | 需重写 |
| 别集 | 按诗题分，标题即诗题 | 需改 |

**做法**：先打印全书的"非缩进行"，人工判断哪些是标题、哪些是正文。

```bash
awk 'NR>=1 && $0!="" && $0 !~ /^\t/ {print NR": "$0}' book.txt | head -100
```

### 3.2 类型体系

**18 类不是圣经。** 按正交性原则裁剪/扩展：

| 情况 | 处理 |
|---|---|
| 某类在本书几乎不出现 | 保留定义但不标（本项目 `[` 刑法仅 4 处） |
| 本书有特殊对象 | **新增类型**（本项目新增 `^` 的联语术语族） |
| 某类界限模糊 | 明确归入某一类并在文档中声明 |

**新增类型的判据**：

```
① 这个对象在本书中大量出现吗？
② 它能被现有 18 类之一覆盖吗？
③ 它与现有类型正交吗（不会同一词归两类）？
```

三个都"是/否/是"才新增。

### 3.3 领域校验

**这是最需要重做的一层。**

问：**这本书有什么形式约束？**

| 书型 | 可自动检查的约束 |
|---|---|
| 联话 | 上下联等长、末字不同 |
| 诗话 | 诗题与诗句的对应、韵脚 |
| 词话 | 词牌与字数、平仄 |
| 笔记 | **几乎没有硬约束** → 领域校验很弱 |

**本项目经验**：联话的"等字数"帮我们抓出了两个系统性错误。
**若你的文本没有硬约束，就要想别的领域指标**
（如"每段应有作者/出处""某类实体密度应在某区间"）。

### 3.4 词表

**必须重建，不能复用。**

理由：词表是**为特定文本的词汇分布**优化的。
本项目的地名词表含 1,441 条，其中 30 余条被剔除——
这些剔除只对本书成立。

**可复用的是"构建方法"**（SKILL_03b），不是词表内容。

## 四、应当拒绝清单

有些东西**不该继承**，因为它们是为原文体设计的。

### 4.1 动词层（本项目已拒绝）

`⟦◈⟧` 是为**叙事史书**设计的（伐/攻/杀/诛）。
在**描写性/评点性**文本里，这些动词几乎不出现，
硬套会得到大量误标。

**判据**：你的文本有大量"谁对谁做了什么"吗？
有 → 可考虑动词层；无 → 不要。

### 4.2 事件与关系层（本项目未做）

史书要抽"事件"（战役、即位、改革）。
联话的"事件"是"某人在某地题了一副联"——
粒度完全不同，不能套用史书的事件模型。

### 4.3 特定文体规则

| 规则 | 只对哪种书成立 |
|---|---|
| 上下联等长 | 对联 |
| 上仄下平 | 对联（本项目都未做，见 SKILL_05 §5） |
| 太史公曰/赞 的块标记 | 史记体例 |
| 三家注分层 | 史记版本特征 |

## 五、五步落地流程

### 步骤 0：摸底（不改一行代码）

```bash
wc -l book.txt
head -100 book.txt          # 看开头结构
grep -n '^[^　 \t]' book.txt | head -80   # 所有非缩进短行
grep -c '。' book.txt       # 句子规模
```

产出：**一份结构清单**（哪些行是标题、哪些是正文、有无目录/附注）。

### 步骤 1：结构先行（不标一个实体）

- 写 `BOOKS` / `HEADINGS` 常量
- 实现 `parse_document()`
- 验证：段落数与源文件缩进行数一致

**这一步不产出研究价值，但必须最先做。**
结构返工 = 全部编号与标注作废。

### 步骤 2：类型设计

- 用正交性检验裁剪 18 类
- 识别本书特有的对象，决定是否新增类型
- 写进 SPEC

### 步骤 3：词表构建

按 SKILL_03b 的流程：
**挖候选 → 逐条查证语境 → 剔除同形词 → 长词优先**。

### 步骤 4：文体层（若需要）

若你的文本有"联""诗""词"这类成对/定长结构，
参照 SKILL_04 设计标记形状：

```
问：标记要不要包裹？
包裹 → 内部无法再标实体
不包裹 → 用前置零宽标记（本项目选择）
```

### 步骤 5：领域校验 + 多轮反思

按 SKILL_05 / 07：
- 找出本书的形式约束
- 算出基线指标
- 逐轮把异常样本压下去

## 六、迁移检查清单

### 6.1 设计阶段

- [ ] 已摸清全书结构（标题/正文/目录/附注）
- [ ] 已确认本书的核心对象
- [ ] 已列出本书的形式约束（哪些可自动检查）

- [ ] 结构先行，段落数校验通过
- [ ] 词表逐条查证过（不是批量导入）
- [ ] 每加一个词都重跑过校验
- [ ] 文体层标记不破坏实体标注

### 6.3 验收阶段

- [ ] 格式校验通过
- [ ] 领域指标达到预期（先定阈值再算）
- [ ] 异常样本已逐条读过
- [ ] 规律库已建立（哪怕只有 5 条）

## 七、常见误判

| 误判 | 后果 | 正解 |
|---|---|---|
| 直接复用上本书的词表 | 大量同形词误标 | 重建 |
| 跳过结构直接标实体 | 结构返工时全废 | 结构先行 |
| 照搬领域校验规则 | 校验出无意义的告警 | 按本书约束重写 |
| 追求 100% 覆盖率 | 引入大量错标 | 精度优先 |
| 只看格式校验 | 系统性错误被掩盖 | 加领域校验 |

## 八、FAQ

**Q：迁移一部新书大概要多久？**
A：以本项目（2,588 行 / 33 万字）为参照，
结构与实体骨架约 1 天，词表逐条查证是主要工作量（数天），
领域校验与反思另需 1–2 轮。

**Q：能不能做成通用工具自动适配？**
A：**结构与符号层可以**（它们与文体无关）。
类型设计与领域校验**不能**——那正是需要人判断的部分。

**Q：怎么判断迁移成功了？**
A：三个信号：
① 领域指标达到阈值；② 异常样本逐条读过后都合理；
③ 规律库里记录了本书特有的坑（说明真的读进去了）。
