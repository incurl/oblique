# SKILL 03b: 词表构建与同形词剔除

> **核心理念**：**词表的质量不取决于收了多少，而取决于剔除了多少。**
> 一个与普通词同形的地名，会造成成百上千次误标。

## 三、构建流程

### 3.1 第一步：从文本中挖候选，不要凭空列

**错误做法**：从全国地名表导入 1,500 个县名。
**后果**：大量与普通词同形的词被误标。

**正确做法**：先看文本里实际出现了什么。

```python
import re, collections
s = open('楹联丛话全编.txt', encoding='utf-8').read()

# 例：挖"引号前的人名"作为诗人候选
pre = collections.Counter()
for m in re.finditer(r'([\u4e00-\u9fff]{2,4})“', s):
    pre[m.group(1)] += 1
print(pre.most_common(80))
```

### 3.2 第二步：逐条查证语境

**这是不可跳过的一步。** 对每个候选词，把它的所有出现处打印出来：

```python
for p in doc.walk():
    if p.kind != 'paragraph': continue
    for m in re.finditer('万安', p.text):
        print(f'{p.id}: {p.text[max(0,m.start()-20):m.end()+20]}')
```

输出：

```
页: 瑞启万安殿外，矞云垂北极            ← 殿名，不是地名
页: 成化戊戌，庶常安徽倪进贤，出入万安之门  ← 人名（明代宦官万安）
页: 第一滩在万安县                    ← 县名 ✅
```

**四条判据**：

1. 该词在这个语境里是**专名**吗？
2. 是专名的话，**属于哪一类**？
3. 有没有更长的词应该优先匹配（"万安殿"vs"万安"）？
4. 所有出现处都一致吗？**只要有一处是普通词，就该进黑名单。**

### 3.3 第三步：把剔除的收进黑名单

```python
AMBIGUOUS_PLACES = set("""
余庆 安定 永宁 永平 永福 永兴 永丰 永新 永康 永明 永寿 永和
清水 清溪 清平 太平 万年 名山 江山 文昌 金门 同官 白水 感恩
长子 安仁 修文 武功 阳春 凌云 文山 齐东 和平 平原 新城 新安
万安 云霄 汾阳 仁寿 新建 华亭 紫阳 龙门 建阳 无为
""".split())
PLACES -= AMBIGUOUS_PLACES
```

**注意：剔除 ≠ 丢失。** 这些词仍可能在别处以**别的类型**出现：

| 词 | 从地名剔除后 | 仍作为 |
|---|---|---|
| `紫阳` | ✅ 剔除 | 人名（朱熹号紫阳） |
| `汾阳` | ✅ 剔除 | 人名（郭子仪封汾阳王） |
| `建阳` | ✅ 剔除 | 该处实为「重建·阳朔县」 |
| `龙门` | ✅ 剔除 | 概念（科举典故） |

### 3.4 第四步：长词优先解决一部分冲突

有些冲突不必剔除，加长词即可：

```python
PLACES |= {"文昌宫", "长乐宫", "无为州", "阳明书院"}   # 长词压住短词
```

`文昌宫`（3 字）会先于 `文昌`（2 字）被选中，
于是建筑名不再被误标成神祇。

## 四、本项目踩过的坑

### 4.1 地名：与普通词同形

| 误标 | 语境 | 应为 |
|---|---|---|
| `〖=万安〗` | 瑞启万安殿外 | 万安殿 |
| `〖=云霄〗` | 只履上云霄 | 天空 |
| `〖=仁寿〗` | 篆凝仁寿字 | 祝寿语 |
| `〖=汾阳〗` | 报君以士识汾阳 | 郭子仪 |
| `〖=建阳〗` | 重建阳朔县书院 | 阳朔 |
| `〖=常山〗` | 号常山虎将 | 赵云 |
| `〖=龙门〗` | 龙门声价最高时 | 科举典故 |
| `〖=紫阳〗` | 朱紫阳夫子家训 | 朱熹 |

### 4.2 朝代：单字极易误标

`明`、`周`、`夏`、`虞` 在古文里首先是普通字。

```python
# ❌ 只看单字：聪明人 → 明朝人；夏初 → 夏朝初年
# ✅ 要求后接朝代词
SINGLE_DYNASTY_RE = re.compile(r"(秦|汉|魏|蜀|吴|唐|宋|元|明|清)(?=代|朝|室|末|初|世|人|以来)")
# 且「聪明人」要额外排除
if m.group(0) == "明" and text[m.start()-1:m.start()] == "聪":
    continue
# 周/夏/虞/商 更严格，只认「代/朝/室」
STRICT_DYNASTY_RE = re.compile(r"(周|夏|虞|商)(?=代|朝|室)")
```

### 4.3 人名：常见词陷阱

| 词 | 问题 | 处理 |
|---|---|---|
| `老子` | 多为自称"我"（"任老子婆娑风月"） | **删除**，只留 `李耳` |
| `庄子` | 可指"村庄"（"谁家庄子"） | **删除**，只留 `庄周` |
| `孙子` | 多为"grandson" | **删除** |
| `百龄` | 多为"百岁" | 只用 `百文敏` |
| `成宪` | 语境确认全是人名 | 保留 |

## 五、禁止事项与推荐做法

### 5.1 禁止

❌ **从外部大词表整批导入** —— 会带来大量同形词误标。

❌ **只看词不看语境** —— 同一个词在不同段落可能属于不同类型。

❌ **批量替换式修正** —— "看起来像"的字眼必须逐个查证（见 SKILL_07 Y10）。

### 5.2 推荐

✅ **先挖候选、再逐条查证** —— 词表规模不重要，精度重要。

✅ **剔除的词记进黑名单并写注释** —— 否则下一个人会再加回来。

✅ **长词优先于短词** —— 能用长词解决就不必拉黑。

✅ **每次改词表都重跑校验** —— 一个词条可能影响上百处。

## 六、工具与脚本

| 位置 | 内容 |
|---|---|
| `scripts/yinglian_dict.py` | 全部词表 + `AMBIGUOUS_PLACES` |
| `scripts/yinglian_lib.py` → `_alternation()` | 词表 → 按长度降序的正则 |

```python
def _alternation(terms):
    """词表编译成正则，长的排前面，保证长词优先匹配。"""
    return "|".join(re.escape(t) for t in sorted(terms, key=len, reverse=True))
```

## 八、FAQ

**Q：为什么不干脆用模型做 NER？**
A：三个理由：① 联话大量长尾专名，模型也认不出；
② 规则的错误可枚举、可修正、可复算，模型的一次批量标注错误是弥散的；
③ 本项目追求"可审计"而非"全自动"。

**Q：黑名单会无限膨胀吗？**
A：不会。真正需要剔除的不过几十个。
大部分冲突用"长词优先"就解决了。

**Q：词表要不要收常见姓氏？**
A：不要单独收。姓氏本身不是人名实体，
只收"姓+名"或"字/号"的完整形式。
