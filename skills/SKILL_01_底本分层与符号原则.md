# SKILL 01: 底本分层与符号原则

> **核心理念**：**先分清"谁写的"，再决定"怎么标"。**
> 把整理者的话当成作者原文标注，是这类工程最常见、也最难被发现的事故。

---

## 一、任务定义

### 1.1 何时使用

- 拿到一份新的电子文本，准备做语义标注
- 要在既有体系里新增实体类型或新符号
- 怀疑某段文字"不太像原文"

### 1.2 输入与产出

| | 内容 |
|---|---|
| 输入 | 原始 `.txt`（只读） |
| 产出 | ① 底本分层结论（哪些行属于哪一层）<br>② 符号约定表（写进 SPEC） |
| 前置 | 无 |
| 后继 | [SKILL_02 结构切分](SKILL_02_结构切分与段落编号.md) |

## 二、底本分层：四种来源必须分开

《楹联丛话全编.txt》不是"一部书"，而是**四层材料的拼接**。
不分层就直接标注，会把现代整理者的话标成梁章钜的话。

| 层 | 位置 | 性质 | 处理 |
|---|---|---|---|
| **A. 电子本目录** | 第 4–78 行 | 扫描站自动生成 | **排除**，程序重建 |
| **B. 现代作者简介** | 第 79–88 行 | 今人撰写的传记 | 保留，标 `::: 小传` |
| **C. 整理者校注** | 第 1043–1048 行 | 「恶人谷注」按语 | 保留，标 `::: 校注` |
| **D. 梁章钜原文** | 第 89–2588 行（除 C） | 真正的底本 | 正文主体 |

### 2.1 为什么目录必须排除

第 4–78 行是内容目录：

```
序
自序
卷之一
故事
卷之二
应制
...
```

它与正文重复。两种做法：

- ❌ 当正文收录 → 读者看到一份重复目录，且这段"文字"不是梁章钜写的
- ✅ 排除，由结构树重建 → 目录与正文永远一致（同一棵解析树生成）

**本项目选后者。** 判据：**这段文字如果是作者写的，才进正文。**

### 2.2 为什么"小传""校注"要保留而不删

现代附注包含有用信息（作者生卒、版本来源），删掉是损失。
但混进正文会污染语料。

解法：**用 Fenced Div 标出块级来源**：

```markdown
::: 小传
[0.1] 〖◆清〗代〖^楹联〗大师〖@梁章钜〗(1775-1849年)，字臣林……
:::

::: 校注
[2.11.38] 恶人谷注：
[2.11.38.1] ①第一字为上下各二"雲"相叠……
:::
```

渲染时用不同底色，读者一眼能分辨"这是原文还是后人加的"。

### 2.3 判断方法

对任何可疑文本，问三个问题：

1. **这段文字在说"书的内容"，还是在说"书本身"？**
   后者（目录、凡例、出版说明）通常不是原文。
2. **它提到了作者身后的年份/事件吗？**（如 "1775-1849"、"电子本"）
3. **它的语气是"整理"还是"著述"？**（"恶人谷注"、"原收于…"）

## 三、符号原则：三个集合必须分离

### 3.1 为什么符号会打架

标记要嵌进中文文本，必须保证**解析无歧义**。三个集合若重叠，
同一个符号在不同上下文有两义，正则与渲染全会出错。

### 3.2 三个集合

| 集合 | 成员 | 归属 | 约束 |
|---|---|---|---|
| **标点集合** | `。，、；：""''《》` | **原文的一部分** | 只允许 CJK 全角，禁半角 |
| **标注集合** | `〖〗` `〘〙` `⟦⟧` | 语义标记 | 用罕见 Unicode，原文不出现 |
| **Markdown 集合** | `# * [ ] \| _ ~` | 文档语法 | 只出现在行首或标记外 |

**核心规则**：**标点永远不进入实体边界**。

### 3.3 已知的不严格处（必须知道）

18 个类型标记中有 8 个与 Markdown 符号同形：

| 符号 | 类型 | Markdown 用途 | 风险 |
|---|---|---|---|
| `#` | 身份 | 标题 | 低（被 `〖〗` 包住） |
| `_` | 思想 | 斜体 | 低 |
| `[` | 刑法 | 链接/段号 | 中（视觉混淆） |
| `$` | 数量 | 数学公式 | 低 |
| `:` | 礼仪 | 自定义块 `:::` | 低 |
| `{` | 典籍 | 属性语法 | 低 |
| `~` | 族群 | 删除线 | 低 |
| `\|` | 消歧分隔符 | 表格分隔符 | **中（见 §3.4）** |

**技术上安全**（都在 `〖〗` 内部），但**可读性略差**。
这是继承来的取舍，不是疏忽。新增符号时请避开这 8 个。

### 3.4 ⚠️ 消歧竖线在 Markdown 表格里会炸

`〖@少穆|林则徐〗` 里的 `|` 在 **Markdown 表格单元格内**会被当成列分隔符，
GFM 在解析行内代码**之前**就切分单元格。

```markdown
❌ | `@` | 人名 | `〖@少穆|林则徐〗` | 1,572 |     ← 被切成 5 列，表格错位
✅ | `@` | 人名 | `〖@少穆\|林则徐〗` | 1,572 |    ← 转义后正常
```

**规则**：写进 Markdown 表格时，`|` 一律转义为 `\|`；
在围栏代码块内则不用转义。

## 四、`〖TYPE 内容〗` 语法定义

### 4.1 三种括号，三个层次

| 括号 | Unicode | 层次 | 格式 | 例 |
|---|---|---|---|---|
| `〖〗` | U+3016/3017 | **名词实体**（世界中的对象） | `〖TYPE 内容〗` | `〖@林则徐〗` |
| `〘〙` | U+3018/3019 | **修辞**（语言层） | `〘※成语〙` | `〘※脍炙人口〙` |
| `⟦⟧` | U+27E6/27E7 | **动词**（世界中的行为） | `⟦◈伐⟧` | 本项目未启用 |

**为什么分三种**：它们语义层级不同。
把成语混进实体层，检索"人名"时会捞出成语。

### 4.2 内联消歧

```
〖TYPE 显示名|规范名〗
```

- 显示名 = 原文中的写法，渲染时显示它
- 规范名 = 索引与链接用的唯一键

例：`〖@少穆|林则徐〗` 显示"少穆"，索引记"林则徐"。

### 4.3 可逆性要求

**去除全部标记后，必须逐字还原原文。**

这决定了标记只能"加"，不能"改"。具体地：

- 不能在标记内调整标点（`〖@刘邦，〗` ❌）
- 不能把原文的《》并进实体（`〖{《春秋》}〗` ❌，应写 `《〖{春秋〗》` ✅）
- 不能因为"看起来多余"就删字

详见 [SKILL_05](SKILL_05_形制校验.md) 的校验实现。

## 五、禁止事项与推荐做法

### 5.1 禁止

❌ **把电子本目录当正文收录** —— 那是整理者的产物，不是作者原文。

❌ **删除现代附注而不留痕** —— 信息损失且不可追溯；应保留并标块。

❌ **混用半角标点** —— 破坏符号三分原则，且校验会拦下。

❌ **在表格里写裸 `|`** —— 会让整张表列数错位（见 §3.4）。

❌ **新增与 Markdown 冲突的符号** —— 除非有充分理由，否则选罕见 Unicode。

### 5.2 推荐

✅ **先列"来源清单"再动手** —— 本项目四层材料，
每层都有明确行号区间，写进代码常量（`BOOKS` / `HEADINGS` / `AUTHOR_INTRO_*`）。

✅ **保留可疑材料并标注，而不是丢弃** —— 保留 + `::: 校注` 优于静默删除。

✅ **符号集写进 SPEC** —— 让下一个 Agent 不必猜。

## 八、FAQ

**Q：能不能干脆把目录也标一遍，省得重建？**
A：不行。目录是"书的索引"，不是"书的内容"。
标了它，`entities.json` 里会出现一批重复计数，
而且重建目录能保证与正文永不失同步。

**Q：`一作`、`见上` 这类词属于哪一层？**
A：属于**校勘层**，不是作者原文。它们由 [SKILL_04](SKILL_04_联语识别.md) §六处理
（剥离并记入 `editorial_markers`）。

**Q：为什么不用 XML/TEI？**
A：见 [references/源流与延伸阅读.md](../skills/references/源流与延伸阅读.md)。
一句话：本项目要的是**人眼可读 + Git 可 diff**，
XML 会让原文不可读、diff 充满标签噪音。
